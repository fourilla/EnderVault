# Optional VPN Egress

EnderVault can run selected managed outbound HTTP requests through a private
Gluetun/OpenVPN proxy. The NAS web UI, file responses, login, Passkey, and
Telegram traffic remain on the normal network.

VPN support is optional. `compose.yaml` still runs the application without VPN
permissions or VPN credentials.

## Supported VPN Input

EnderVault uses one provider-independent OpenVPN path. The user does not select
a Gluetun native provider.

Provide:

```text
docker/secrets/vpn/config/custom.ovpn
.env
```

- Put the selected `.ovpn` profile in `config`.
- Put any certificate or key files referenced by the profile under the same
  directory and use relative paths in the profile.
- Set `ENDERVAULT_OPENVPN_USER` and `ENDERVAULT_OPENVPN_PASSWORD` in the
  repository-root `.env` file.
- If the profile does not use username/password authentication, keep both
  values empty.

All files under `docker/secrets` are excluded from Git and the Docker build
context. An OVPN profile can contain embedded certificates or private keys, so
treat it as a credential.

Compose reads the OpenVPN credentials from `.env` and exposes them only to the
VPN service as files under `/run/secrets`. They are not copied into the image or
placed directly in the Gluetun container environment. The local `.env` file is
plain text, so keep it out of Git and restrict access to the host account.

## Environment Paths

Copy `.env.example` to `.env` and change paths when necessary.

```properties
ENDERVAULT_VPN_STATE_DIR=./docker/runtime/vpn
ENDERVAULT_VPN_CONFIG_DIR=./docker/secrets/vpn/config
ENDERVAULT_VPN_CONFIG_NAME=custom.ovpn

ENDERVAULT_OPENVPN_USER=
ENDERVAULT_OPENVPN_PASSWORD=
```

`ENDERVAULT_VPN_CONFIG_NAME` must be a plain `.ovpn` or `.conf` file name. One
VPN service uses one selected profile. Other certificate files may coexist in
the directory.

## Profile Preparation

Gluetun deliberately avoids resolving a custom profile's endpoint hostname
before the tunnel is available. EnderVault accepts that one initial direct DNS
lookup in exchange for a provider-independent setup.

Before Gluetun starts, the one-shot `vpn-config` service:

1. reads the original profile from the read-only secret directory;
2. resolves every active `remote` hostname through the container's normal DNS;
3. rewrites relative certificate/key references to the read-only container
   path;
4. atomically writes an executable copy to
   `docker/runtime/vpn/generated/<profile-name>`;
5. exits successfully, allowing the `vpn` service to start.

The original OVPN file is never modified. Gluetun reads the generated profile
but continues to read certificates and keys from the read-only input mount.

The initial DNS resolver and network operator can observe that the VPN endpoint
hostname was queried. A valid OpenVPN profile should still authenticate the VPN
server using its CA/certificate, so redirecting DNS normally causes connection
failure rather than a successful impersonation. DNS manipulation can still
cause denial of service, censorship, or stale endpoint selection. A stricter
resolver/bootstrap policy remains a possible future improvement.

The preparation step runs during Compose startup, not every automatic Gluetun
process restart. Run `docker compose up -d` again when the provider changes its
endpoint address or after replacing the source profile.

## EnderVault Application Settings

The VPN Compose overlay owns the container-internal topology and injects these
effective Spring settings automatically:

```properties
nas.outbound.vpn.enabled=true
nas.outbound.vpn.proxy-host=vpn
nas.outbound.vpn.proxy-port=8888
nas.outbound.vpn.tunnel-health-url=http://vpn:9999/
nas.outbound.vpn.control-url=http://vpn:8000
nas.outbound.vpn.control-api-key-file=/var/run/endervault-vpn/auth/control-api.key
nas.outbound.vpn.profile-name=custom.ovpn
```

Do not copy these Docker service addresses into a Standalone JAR deployment.
The `vpn` hostname exists only on the private Compose network. Values written
to `endervault-nas.properties` are lower precedence than these Docker
environment overrides after a container restart.

The application properties still own behavior and tuning that is not part of
the Compose topology, for example:

```properties
nas.outbound.vpn.health-connect-timeout-ms=1500
nas.outbound.vpn.health-request-timeout-ms=3000
nas.outbound.vpn.health-check-interval-ms=30000

# Startup default only. Runtime Topbar changes are held in server memory.
nas.outbound.initial-route=direct
```

The proxy and health ports are exposed only inside the private Compose network.
The Gluetun Control API is also available only on that network and requires the
API key generated by the `vpn-config` service.

## Run

Validate the effective Compose model:

```bash
docker compose \
  --env-file .env \
  -f compose.yaml \
  -f compose.vpn.yaml \
  --profile vpn \
  config --quiet
```

Start EnderVault and VPN:

```bash
docker compose -f compose.yaml -f compose.vpn.yaml --profile vpn up -d --build
```

Check preparation and tunnel logs:

```bash
docker compose -f compose.yaml -f compose.vpn.yaml logs vpn-config vpn
```

Stop the same Compose project:

```bash
docker compose -f compose.yaml -f compose.vpn.yaml --profile vpn down
```

## Runtime Policy

- The Topbar switches the server-wide managed outbound route between Direct
  and VPN.
- Bookmark metadata captures the current route when its operation starts.
- Remote Download may use the global route or explicitly override it for that
  task.
- A running task keeps the route selected at task creation time.
- `VPN_REQUIRED` never silently falls back to Direct when the proxy or tunnel
  is unhealthy.
- VPN routing does not replace SSRF validation.

## Current Limitations

- Only OpenVPN profiles are supported. WireGuard may be added later.
- Gluetun currently consumes only the first `remote` entry from a custom
  profile, even though preparation resolves every entry.
- Absolute external certificate/key paths are rejected; keep referenced files
  inside the profile directory.
- Endpoint DNS is resolved once per profile-preparation run. There is no TTL
  cache or automatic re-resolution while Gluetun is restarting.
- OVPN files are trusted administrator input. Download profiles only from a
  trusted VPN provider because OpenVPN profiles can contain powerful options.
- Tunnel health means Gluetun considers the tunnel healthy; it does not prove
  a particular country, public IP, or absence of every possible DNS leak.
